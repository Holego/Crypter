# Crypter

Утилита командной строки для **хеширования** и **шифрования** файлов, а также для
упаковки программ в самозапускающийся лаунчер. Один скрипт на Python, без лишних
зависимостей (кроме [`cryptography`](https://pypi.org/project/cryptography/)).

## Возможности

- Хеширование файла несколькими алгоритмами за один проход.
- Шифрование/расшифровка файла паролем (AEAD, потоковая обработка — размер файла не ограничен памятью).
- `pack` — упаковка любой программы в самозапускающийся `.py`-лаунчер.
- `--standalone` — сборка самодостаточного исполняемого файла (на целевой машине Python не нужен).
- `--sign` — подпись собранного `.exe` вашим сертификатом (Windows).
- `bundle` — объединение нескольких программ в один файл; все запускаются **открыто**.
- Интерактивное меню, если запустить без аргументов.

## Установка

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt      # cryptography; pyinstaller — для --standalone
```

Требуется Python 3.10+.

## Использование

### Хеширование

```bash
python crypter.py hash file.txt                      # sha256 по умолчанию
python crypter.py hash file.txt -a sha256 -a md5     # несколько алгоритмов
python crypter.py hash file.txt --all                # все сразу
```

Доступные хеши: `md5`, `sha1`, `sha256`, `sha512`, `sha3_256`, `sha3_512`,
`blake2b`, `blake2s` (md5/sha1 — только как контрольная сумма).

### Шифрование паролем

```bash
python crypter.py encrypt file.txt                   # -> file.txt.enc (AES-256-GCM)
python crypter.py encrypt file.txt -a chacha20       # ChaCha20-Poly1305
python crypter.py decrypt file.txt.enc               # -> file.txt
```

Ключ выводится из пароля через `scrypt`. Алгоритм записывается в заголовок, поэтому
при расшифровке указывать его не нужно. Повреждение файла или неверный пароль
обнаруживаются (аутентифицированное шифрование). Пароль можно передать через
переменную окружения `CRYPTER_PASSWORD`.

### Упаковка в самозапускающийся лаунчер

```bash
python crypter.py pack myprog.py                     # -> myprog_packed.py (нужен Python)
python crypter.py pack myprog.py --standalone        # -> myprog_app (Python не нужен)
python crypter.py pack program.exe -i none           # любой бинарник, запуск напрямую
python crypter.py pack app.js -i node                # свой интерпретатор
```

Лаунчер при запуске расшифровывает программу, запускает её, передаёт аргументы
командной строки насквозь и возвращает её код выхода. Python-программа
выполняется прямо в процессе лаунчера (без временного файла); остальное —
через временный файл, который удаляется после выхода.

### Объединение программ (bundle)

```bash
python crypter.py bundle prog1.py prog2.exe          # по очереди
python crypter.py bundle prog1.py prog2.exe -p       # одновременно
python crypter.py bundle prog1.py prog2.py --standalone
```

Все программы запускаются **открыто**, их вывод виден. Итоговый код выхода —
наибольший из кодов (ненулевой, если хоть одна упала).

### Подпись .exe (Windows)

```bash
python crypter.py pack myprog.py --standalone --sign mycert.pfx --sign-password ПАРОЛЬ
```

Нужен ваш сертификат `.pfx` и `signtool` (из Windows SDK). Сертификат вы получаете
сами: покупаете в центре сертификации для публичной раздачи или делаете
самоподписанный для своих машин. Подпись подтверждает автора и убирает
предупреждения SmartScreen/антивируса — с шифрованием содержимого не связана.

## Сборка Windows .exe

PyInstaller собирает файл **под ту ОС, где идёт сборка**, — кросс-компиляции нет.
Чтобы получить Windows `.exe`, запускайте `--standalone` на Windows (Python +
`pyinstaller` нужны только на сборочной машине, на целевой — нет).

## Важно про уровень защиты

- **`encrypt`/`decrypt`** — настоящее шифрование: без пароля данные не прочитать.
- **`pack`/`bundle` без пароля** — это **обфускация**, а не стойкая защита: ключ
  вшит внутрь лаунчера, и подготовленный человек может его извлечь. Защищает от
  обычного пользователя, но не от специалиста по реверс-инжинирингу.
